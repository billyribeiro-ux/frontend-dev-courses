# Form Actions Basics

## What Form Actions Are and Why They Exist

HTML forms have been sending data to servers since the 1990s. A `<form method="POST">` collects user input, the browser serializes it, sends an HTTP POST request, and the server processes the data and responds with a new page. No JavaScript required. This is the most resilient, accessible, and universally supported way to mutate data on the web.

SvelteKit embraces this pattern with **form actions** -- server-side functions that process form submissions. They are SvelteKit's answer to the question: "How do I handle POST requests in a page-centric routing model?"

Form actions live in `+page.server.ts` alongside your load functions. When a user submits a form, SvelteKit calls the matching action, processes the data, and re-renders the page with fresh data. The critical design decision is that form actions work entirely without client-side JavaScript. The browser's native form submission handles everything. When JavaScript is available, `use:enhance` can upgrade the experience to feel like a single-page app -- but the server code stays identical.

This is **progressive enhancement** at the architectural level. You are not building a client-side app that happens to talk to a server. You are building a server-side app that happens to get enhanced by a client.

### Why Not Just Use API Routes?

SvelteKit has `+server.ts` for building REST endpoints. You could use `fetch()` to POST data to those endpoints from the client. But form actions offer several advantages:

1. **Progressive enhancement**: Forms work without JavaScript. API routes require JavaScript to call `fetch()`.
2. **Automatic data reloading**: After a form action completes, SvelteKit automatically re-runs the page's `load` functions, ensuring the UI reflects the latest data. With API routes, you must manually invalidate data.
3. **Type-safe data flow**: The `ActionData` type generated by SvelteKit gives you type-safe access to the action's return value in the page component.
4. **CSRF protection**: SvelteKit automatically checks the `Origin` header on form submissions, protecting against cross-site request forgery. With raw API routes, you must implement this yourself.
5. **Colocation**: Actions live in `+page.server.ts` alongside the page's `load` function. The page's data flow (reading and writing) is in one file, making it easy to reason about.

## The `+page.server.ts` `actions` Export

### The Default Action

The simplest setup is a single default action. Export an `actions` object with a `default` key:

```typescript
// src/routes/contact/+page.server.ts
import type { Actions } from './$types';

export const actions: Actions = {
  default: async ({ request }) => {
    const formData = await request.formData();
    const name = formData.get('name') as string;
    const message = formData.get('message') as string;

    // Process the data -- save to database, send email, etc.
    await db.insert(messages).values({ name, message, createdAt: new Date() });

    return { success: true };
  }
};
```

The corresponding form does not need an `action` attribute -- it automatically submits to the default action:

```svelte
<!-- src/routes/contact/+page.svelte -->
<script lang="ts">
  import type { ActionData } from './$types';

  let { form }: { form: ActionData } = $props();
</script>

<h1>Contact Us</h1>

{#if form?.success}
  <p class="success">Thank you for your message!</p>
{/if}

<form method="POST">
  <label>
    Name
    <input name="name" required />
  </label>
  <label>
    Message
    <textarea name="message" required></textarea>
  </label>
  <button type="submit">Send</button>
</form>
```

The `form` prop contains whatever the action returned. It is `null` on initial page load and populated after a form submission. This is how the server communicates results back to the page.

### How It Works Step by Step

When the user clicks "Send":

1. The browser serializes the form fields into a `FormData` object.
2. The browser sends a POST request to the current URL (the page's route).
3. SvelteKit's server handler intercepts the request and finds the `default` action.
4. SvelteKit calls the action function with a `RequestEvent` object.
5. The action reads `request.formData()`, processes the data, and returns an object.
6. SvelteKit re-runs the page's `load` function (if any) to get fresh data.
7. SvelteKit renders the page with the updated data and the action's return value as `form`.
8. The browser receives the full HTML page and replaces the current page.

Without JavaScript, this is a full page reload. With `use:enhance`, step 8 becomes a DOM patch instead of a full reload.

## RequestEvent in Actions

Every action receives a `RequestEvent` object with access to the full request context. This is the same object that `load` functions, hooks, and API routes receive:

```typescript
import type { Actions } from './$types';
import { fail, redirect } from '@sveltejs/kit';

export const actions: Actions = {
  default: async (event) => {
    // The full RequestEvent object:
    const {
      request,   // The raw Request object (use request.formData() to get form data)
      cookies,   // Read/write cookies (cookies.get(), cookies.set(), cookies.delete())
      locals,    // Shared data set by hooks (e.g., locals.user from auth middleware)
      params,    // Route parameters (e.g., params.id for /posts/[id])
      url,       // The full URL object
      platform,  // Platform-specific context (Vercel, Cloudflare, etc.)
      fetch,     // A server-side fetch that inherits cookies and handles relative URLs
      getClientAddress, // The client's IP address
      setHeaders,       // Set response headers
      isDataRequest,    // Whether this is a data request (from use:enhance) vs full navigation
    } = event;

    // Example: require authentication
    if (!locals.user) {
      throw redirect(303, '/login');
    }

    const formData = await request.formData();
    const title = formData.get('title') as string;

    // Example: use route params
    // For a route like /posts/[id]/edit
    const postId = params.id;

    // Example: set a cookie after form submission
    cookies.set('last_action', 'created_post', {
      path: '/',
      httpOnly: true,
      sameSite: 'strict',
      maxAge: 60 * 60 // 1 hour
    });

    return { success: true };
  }
};
```

### Accessing request.formData()

The `request.formData()` method returns a `FormData` object. It is async because the request body may still be streaming. You call it once per action -- calling it twice will fail because the body stream has already been consumed:

```typescript
export const actions: Actions = {
  default: async ({ request }) => {
    const formData = await request.formData();

    // Get a single value (returns string | File | null)
    const title = formData.get('title') as string;

    // Get multiple values (for checkboxes or multi-selects)
    const tags = formData.getAll('tags') as string[];

    // Check if a field exists (useful for checkboxes -- unchecked = not present)
    const hasNewsletter = formData.has('newsletter');

    // Convert to a plain object (useful for simple forms with unique field names)
    const data = Object.fromEntries(formData);
    // data = { title: 'My Post', content: '...', category: 'news' }

    // Iterate over all entries
    for (const [key, value] of formData.entries()) {
      console.log(key, value);
    }

    return { title, tags, hasNewsletter };
  }
};
```

#### Important: Checkbox Handling

HTML checkboxes only send a value when checked. When unchecked, they send nothing at all:

```html
<input type="checkbox" name="agree" value="yes" />
```

```typescript
// If checked: formData.get('agree') === 'yes'
// If unchecked: formData.get('agree') === null
```


### Using cookies

Actions can read and set cookies, which is essential for session management, preferences, and flash messages:

```typescript
export const actions: Actions = {
  login: async ({ request, cookies }) => {
    const formData = await request.formData();
    const email = formData.get('email') as string;
    const password = formData.get('password') as string;

    const user = await authenticateUser(email, password);

    if (!user) {
      return fail(401, { email, error: 'Invalid credentials' });
    }

    // Set a session cookie
    cookies.set('session_id', user.sessionId, {
      path: '/',
      httpOnly: true,    // Not accessible via JavaScript
      secure: true,       // Only sent over HTTPS
      sameSite: 'lax',    // Sent on top-level navigations
      maxAge: 60 * 60 * 24 * 7 // 7 days
    });

    throw redirect(303, '/dashboard');
  },

  logout: async ({ cookies }) => {
    cookies.delete('session_id', { path: '/' });
    throw redirect(303, '/');
  }
};
```

### Using locals

The `locals` object is populated by hooks (in `hooks.server.ts`) and is available in every action. This is the standard pattern for accessing the authenticated user:

```typescript
    event.locals.user = await getUserFromSession(sessionId);
  }

  return resolve(event);
};
```

### Using params

For routes with dynamic segments, `params` gives you the URL parameters:

```typescript

export const actions: Actions = {

    return { success: true };
  }
};
```

## Returning Data from Actions

Actions can return any JSON-serializable data. This data becomes available in the page component as the `form` prop (or `$page.form`).

### Success Responses

```typescript
export const actions: Actions = {
  default: async ({ request }) => {
    const formData = await request.formData();
    const email = formData.get('email') as string;

    await subscribeToNewsletter(email);

    // Return any data you want the page to display
    return {
      success: true,
      message: 'Subscription confirmed!',
      subscribedEmail: email
    };
  }
};
```

```svelte
<script lang="ts">
  import type { ActionData } from './$types';
  let { form }: { form: ActionData } = $props();
</script>

{#if form?.success}
  <div class="success-banner">
    <p>{form.message}</p>
    <p>We sent a confirmation to {form.subscribedEmail}</p>
  </div>
{/if}
```

The `ActionData` type is auto-generated by SvelteKit based on what your actions return. It is a union of the return types of all your actions, plus `null` (for the initial page load when no action has been submitted).

### Accessing form via $page.form

You can also access action data through the `$page` store, which is useful in layout components or deeply nested components that do not receive the `form` prop directly:

```svelte
<script lang="ts">

</script>

{#if $page.form?.success}
  <div class="toast">Action completed successfully!</div>
{/if}
```

## The fail() Function

The `fail()` function from `@sveltejs/kit` returns a response with a non-2xx status code while preserving the returned data. This is how you communicate validation errors back to the page:

```typescript
import { fail } from '@sveltejs/kit';

export const actions: Actions = {
  default: async ({ request }) => {
    const formData = await request.formData();
    const email = formData.get('email') as string;
    const password = formData.get('password') as string;

    // Validation
    if (!email || !email.includes('@')) {
      return fail(400, {
        error: 'Invalid email address',
        email // Send back the email so the form can repopulate the field
      });
    }

    if (!password || password.length < 8) {
      return fail(400, {
        error: 'Password must be at least 8 characters',
        email // Send back the email (but NEVER send back the password)
      });
    }

    // Check for existing user
    const existingUser = await db.select().from(users).where(eq(users.email, email)).limit(1);
    if (existingUser.length > 0) {
      return fail(409, {
        error: 'An account with this email already exists',
        email
      });
    }

    // Create the user
    await db.insert(users).values({ email, passwordHash: await hashPassword(password) });

    return { success: true, message: 'Account created!' };
  }
};
```

### Why fail() Instead of Just Returning Errors

You might wonder why you cannot just return `{ error: 'something' }` without `fail()`. The difference is the HTTP status code:

- **Without `fail()`**: SvelteKit returns a `200 OK` status. The `form` prop is populated. The `result.type` in `use:enhance` is `'success'`.
- **With `fail(400)`**: SvelteKit returns a `400 Bad Request` status. The `form` prop is still populated. But the `result.type` in `use:enhance` is `'failure'`, and `use:enhance` keeps the form values instead of resetting them.

This distinction matters because `use:enhance` uses the result type to decide whether to reset the form. On success, it clears the fields (the user's input was accepted). On failure, it preserves the fields (the user needs to fix something). If you return errors without `fail()`, `use:enhance` treats it as success and clears the form -- the user loses their input.

### Field-Level Errors

For forms with multiple fields, return an errors object keyed by field name:

```typescript
export const actions: Actions = {
  default: async ({ request }) => {
    const formData = await request.formData();
    const name = formData.get('name') as string;
    const email = formData.get('email') as string;
    const age = formData.get('age') as string;

    const errors: Record<string, string> = {};

    if (!name || name.trim().length < 2) {
      errors.name = 'Name must be at least 2 characters';
    }

    if (!email || !email.includes('@')) {
      errors.email = 'Please enter a valid email address';
    }

    const ageNum = parseInt(age);
    if (isNaN(ageNum) || ageNum < 13 || ageNum > 120) {
      errors.age = 'Age must be between 13 and 120';
    }

    if (Object.keys(errors).length > 0) {
      return fail(400, {
        errors,
        values: { name, email, age } // Repopulate the form
      });
    }

    // All valid -- proceed
    await saveProfile({ name, email, age: ageNum });
    return { success: true };
  }
};
```

## Named Actions: Multiple Actions on One Page

When a page needs multiple forms -- create, edit, delete, archive -- use named actions. Instead of a single `default` key, give each action a descriptive name:

```typescript
// src/routes/todos/+page.server.ts
import type { Actions, PageServerLoad } from './$types';
import { fail } from '@sveltejs/kit';

export const load: PageServerLoad = async () => {
  const todos = await db.select().from(todosTable).orderBy(todosTable.createdAt);
  return { todos };
};

export const actions: Actions = {
  create: async ({ request, locals }) => {
    if (!locals.user) return fail(401, { error: 'Not authenticated' });

    const formData = await request.formData();
    const text = formData.get('text') as string;

    if (!text?.trim()) {
      return fail(400, { error: 'Todo text is required', action: 'create' });
    }

    await db.insert(todosTable).values({
      text: text.trim(),
      userId: locals.user.id,
      completed: false
    });

    return { success: true, action: 'create' };
  },

  toggle: async ({ request }) => {
    const formData = await request.formData();
    const id = formData.get('id') as string;
    const completed = formData.has('completed');

    await db.update(todosTable)
      .set({ completed })
      .where(eq(todosTable.id, id));

    return { success: true, action: 'toggle' };
  },

  update: async ({ request }) => {
    const formData = await request.formData();
    const id = formData.get('id') as string;
    const text = formData.get('text') as string;

    if (!text?.trim()) {
      return fail(400, { error: 'Todo text cannot be empty', id, action: 'update' });
    }

    await db.update(todosTable)
      .set({ text: text.trim() })
      .where(eq(todosTable.id, id));

    return { success: true, action: 'update' };
  },

  delete: async ({ request }) => {
    const formData = await request.formData();
    const id = formData.get('id') as string;

    await db.delete(todosTable).where(eq(todosTable.id, id));

    return { success: true, action: 'delete' };
  }
};
```

### Targeting Named Actions from Forms

Point each form to its action using the `action` attribute with a `?/actionName` query parameter:

```svelte
<!-- src/routes/todos/+page.svelte -->
<script lang="ts">
  import { enhance } from '$app/forms';
  import type { ActionData, PageData } from './$types';

  let { data, form }: { data: PageData; form: ActionData } = $props();
</script>

<h1>Todos</h1>

<!-- Create form targets the 'create' action -->
<form method="POST" action="?/create" use:enhance>
  <input name="text" placeholder="What needs to be done?" required />
  <button type="submit">Add</button>
</form>

{#if form?.action === 'create' && form?.error}
  <p class="error">{form.error}</p>
{/if}

<ul>
  {#each data.todos as todo (todo.id)}
    <li>
      <!-- Toggle form targets the 'toggle' action -->
      <form method="POST" action="?/toggle" use:enhance>
        <input type="hidden" name="id" value={todo.id} />
        <label>
          <input
            type="checkbox"
            name="completed"
            checked={todo.completed}
            onchange={(e) => e.currentTarget.form?.requestSubmit()}
          />
          {todo.text}
        </label>
      </form>

      <!-- Delete form targets the 'delete' action -->
      <form method="POST" action="?/delete" use:enhance>
        <input type="hidden" name="id" value={todo.id} />
        <button type="submit" aria-label="Delete {todo.text}">Delete</button>
      </form>
    </li>
  {/each}
</ul>
```

The `?/create`, `?/toggle`, and `?/delete` syntax tells SvelteKit which named action to call. The `?/` prefix is important -- it distinguishes action names from regular query parameters.

### How Named Action Routing Works

When SvelteKit receives a POST request to `/todos?/delete`, it:

1. Looks up the route for `/todos` and finds `+page.server.ts`.
2. Parses the `?/delete` from the URL and looks for the `delete` key in the `actions` export.
3. If found, calls that action function. If not found, returns a 404 error.

You cannot have both a `default` action and named actions on the same page. If you define named actions, there is no default -- every form must specify `action="?/actionName"`.

### Cross-Page Action Submission

Forms can submit to actions on other pages by specifying the full path:

```svelte
<!-- From any page, submit to /api/newsletter -->
<form method="POST" action="/newsletter?/subscribe">
  <input name="email" type="email" required />
  <button type="submit">Subscribe</button>
</form>
```

This works, but after submission, SvelteKit redirects back to the page that submitted the form (not the page that owns the action). The `form` prop on the originating page will contain the action's return value.

## use:enhance Deep Dive

The `use:enhance` directive from `$app/forms` upgrades a plain HTML form into a JavaScript-enhanced experience. It is the bridge between "works without JS" and "feels like a SPA."

### What use:enhance Does Under the Hood

Without `use:enhance`, form submission triggers a full browser navigation:

```
User clicks submit
  -> Browser serializes form data
  -> Browser sends POST request (full page navigation)
  -> Server runs the action, returns new HTML
  -> Browser replaces the entire page
```

With `use:enhance`, the same form submission is intercepted:

```
User clicks submit
  -> SvelteKit calls event.preventDefault()
  -> SvelteKit serializes the form data
  -> SvelteKit sends a fetch() POST request with the same data
  -> Server runs the same action, returns the result as JSON
  -> SvelteKit processes the result:
      - On success: invalidates load functions, updates $page.form, resets form
      - On failure: updates $page.form (keeps form values)
      - On redirect: navigates via client-side routing
```

The server code stays exactly the same. The directive is purely a client-side upgrade. If JavaScript has not loaded yet, the form falls back to native browser submission -- which still works because your server action handles it either way.

### Basic Usage

```svelte
<script lang="ts">
  import { enhance } from '$app/forms';
</script>

<form method="POST" action="?/create" use:enhance>
  <input name="title" required />
  <button type="submit">Add</button>
</form>
```

This single directive gives you:

1. No page reload on submit
2. Automatic data reloading (all `load` functions re-run)
3. Form reset on success
4. `$page.form` updated with the action's return value
5. Client-side navigation on redirects

## Custom enhance Callbacks

Pass a function to `use:enhance` to customize the behavior. The function runs **before** the request is sent and can return a callback that runs **after** the server responds:

```svelte
<script lang="ts">
  import { enhance } from '$app/forms';

  let submitting = $state(false);
  let errorMessage = $state('');
</script>

<form
  method="POST"
  action="?/create"
  use:enhance={({ formData, formElement, action, cancel, submitter }) => {
    // === BEFORE SUBMISSION ===
    // This code runs when the user clicks submit, before the fetch request.

    // 'formData' - the FormData object (you can read, modify, or add fields)
    const title = formData.get('title') as string;

    // 'formElement' - the HTML form element
    // 'action' - the URL the form will submit to (e.g., '/todos?/create')
    // 'submitter' - the button/element that triggered the submission
    // 'cancel()' - call this to abort the submission entirely

    // Client-side validation
    if (title.length < 3) {
      errorMessage = 'Title must be at least 3 characters';
      cancel(); // Prevent the request from being sent
      return;   // No return callback needed
    }

    // Show loading state
    submitting = true;
    errorMessage = '';

    // You can modify formData before it's sent:
    formData.set('submittedAt', new Date().toISOString());

    // === AFTER SUBMISSION ===
    // Return an async function to handle the response
    return async ({ result, update, formData: fd, formElement: fe }) => {
      submitting = false;

      // 'result' has one of four types:
      // { type: 'success', status: 200, data: {...} }
      // { type: 'failure', status: 400, data: {...} }
      // { type: 'redirect', status: 303, location: '/somewhere' }
      // { type: 'error', status: 500, error: {...} }

      if (result.type === 'success') {
        // Let SvelteKit handle the default behavior
        await update();
      } else if (result.type === 'failure') {
        errorMessage = (result.data as { error?: string })?.error ?? 'Something went wrong';
        // Keep form values so user can fix the error
        await update({ reset: false });
      } else if (result.type === 'redirect') {
        // SvelteKit handles redirects automatically if you call update()
        await update();
      } else if (result.type === 'error') {
        // Unexpected server error
        errorMessage = 'An unexpected error occurred. Please try again.';
        // NOT calling update() -- handle entirely ourselves
      }
    };
  }}
>
  <input name="title" required />
  <button type="submit" disabled={submitting}>
    {submitting ? 'Saving...' : 'Add'}
  </button>
</form>

{#if errorMessage}
  <p class="error">{errorMessage}</p>
{/if}
```

### The Before-Submit Object

The function passed to `use:enhance` receives an object with:

| Property | Type | Description |
|---|---|---|
| `formData` | `FormData` | The form's data. You can read, modify, add, or delete fields before submission. |
| `formElement` | `HTMLFormElement` | The HTML form element itself. |
| `action` | `URL` | The URL the form will submit to. |
| `cancel()` | `() => void` | Call to abort the submission entirely. |
| `submitter` | `HTMLElement \| null` | The button or element that triggered the submission. |

### The After-Submit Object

The returned async function receives:

| Property | Type | Description |
|---|---|---|
| `result` | `ActionResult` | The server response: `{ type, status, data?, location?, error? }` |
| `update(opts?)` | `(opts?) => Promise<void>` | Runs SvelteKit's default post-submission behavior. |
| `formElement` | `HTMLFormElement` | The HTML form element. |
| `formData` | `FormData` | The original FormData object. |

### Understanding update()

The `update()` function is where SvelteKit's magic happens. When you call it:

1. It invalidates all `load` functions, causing them to re-fetch data.
2. It updates `$page.form` with the action's return value.
3. It resets the form fields (unless you pass `{ reset: false }`).
4. It handles redirects (navigates to the new URL).

If you do **not** call `update()`, none of this happens. You are in full manual control. This is useful for custom animations, toast notifications, or any case where you want to handle the response entirely yourself -- but be aware that load functions will not re-run and your data may become stale.

```typescript
// Calling update with options
await update();                    // Default: invalidate, update form, reset fields
await update({ reset: false });    // Same but keep form field values
await update({ invalidateAll: false }); // Do not re-run load functions
```

## Form Data Extraction Patterns

### Object.fromEntries() for Simple Forms

When every field name is unique, convert FormData to a plain object:

```typescript
export const actions: Actions = {
  default: async ({ request }) => {
    const formData = await request.formData();
    const data = Object.fromEntries(formData) as {
      title: string;
      content: string;
      category: string;
    };

    // data.title, data.content, data.category are all available
    await createPost(data);
    return { success: true };
  }
};
```

**Caveat**: `Object.fromEntries()` drops duplicate keys. If your form has checkboxes or multi-selects with the same name, only the last value survives. Use `formData.getAll('tags')` for those.

### Validation with Zod

For complex forms, use a validation library like Zod to parse and validate form data in one step:

```typescript
import { z } from 'zod';
import { fail } from '@sveltejs/kit';

const postSchema = z.object({
  title: z.string().min(3, 'Title must be at least 3 characters').max(100),
  content: z.string().min(50, 'Content must be at least 50 characters'),
  category: z.enum(['tutorial', 'news', 'opinion'], {
    errorMap: () => ({ message: 'Please select a valid category' })
  }),
  published: z.coerce.boolean().default(false),
  tags: z.array(z.string()).default([])
});

export const actions: Actions = {
  create: async ({ request }) => {
    const formData = await request.formData();

    // Build the raw data object
    const rawData = {
      ...Object.fromEntries(formData),
      tags: formData.getAll('tags'),
      published: formData.has('published')
    };

    // Validate with Zod
    const result = postSchema.safeParse(rawData);

    if (!result.success) {
      // Convert Zod errors to a field-keyed object
      const errors: Record<string, string> = {};
      for (const issue of result.error.issues) {
        const field = issue.path[0] as string;
        errors[field] = issue.message;
      }

      return fail(400, {
        errors,
        values: rawData
      });
    }

    // result.data is now fully typed and validated
    await db.insert(posts).values(result.data);
    return { success: true };
  }
};
```

### Validation with Valibot

Valibot is a lighter alternative to Zod with a similar API:

```typescript
import * as v from 'valibot';
import { fail } from '@sveltejs/kit';

const ContactSchema = v.object({
  name: v.pipe(v.string(), v.minLength(2, 'Name is too short')),
  email: v.pipe(v.string(), v.email('Invalid email address')),
  message: v.pipe(v.string(), v.minLength(10, 'Message is too short'))
});

export const actions: Actions = {
  default: async ({ request }) => {
    const formData = await request.formData();
    const data = Object.fromEntries(formData);

    const result = v.safeParse(ContactSchema, data);

    if (!result.success) {
      const errors: Record<string, string> = {};
      for (const issue of result.issues) {
        const field = issue.path?.[0]?.key as string;
        if (field) errors[field] = issue.message;
      }
      return fail(400, { errors, values: data });
    }

    await sendContactEmail(result.output);
    return { success: true };
  }
};
```

## Complete Example: Multi-Action Page with Create, Edit, and Delete

Here is a complete, production-quality example of a page with three named actions -- all progressively enhanced:

```typescript
// src/routes/notes/+page.server.ts
import type { Actions, PageServerLoad } from './$types';
import { fail } from '@sveltejs/kit';

// Simulated database
let notes: Array<{ id: string; title: string; body: string; updatedAt: Date }> = [
  { id: '1', title: 'First Note', body: 'Hello world', updatedAt: new Date() }
];

export const load: PageServerLoad = async () => {
  return {
    notes: notes.map(n => ({
      ...n,
      updatedAt: n.updatedAt.toISOString()
    }))
  };
};

export const actions: Actions = {
  create: async ({ request }) => {
    const formData = await request.formData();
    const title = formData.get('title') as string;
    const body = formData.get('body') as string;

    const errors: Record<string, string> = {};
    if (!title?.trim()) errors.title = 'Title is required';
    if (!body?.trim()) errors.body = 'Body is required';
    if (title && title.length > 100) errors.title = 'Title must be under 100 characters';

    if (Object.keys(errors).length > 0) {
      return fail(400, { errors, values: { title, body }, action: 'create' as const });
    }

    const note = {
      id: crypto.randomUUID(),
      title: title.trim(),
      body: body.trim(),
      updatedAt: new Date()
    };
    notes.push(note);

    return { success: true, action: 'create' as const, message: 'Note created!' };
  },

  update: async ({ request }) => {
    const formData = await request.formData();
    const id = formData.get('id') as string;
    const title = formData.get('title') as string;
    const body = formData.get('body') as string;

    const note = notes.find(n => n.id === id);
    if (!note) return fail(404, { error: 'Note not found', action: 'update' as const });

    const errors: Record<string, string> = {};
    if (!title?.trim()) errors.title = 'Title is required';
    if (!body?.trim()) errors.body = 'Body is required';

    if (Object.keys(errors).length > 0) {
      return fail(400, { errors, values: { id, title, body }, action: 'update' as const });
    }

    note.title = title.trim();
    note.body = body.trim();
    note.updatedAt = new Date();

    return { success: true, action: 'update' as const, message: 'Note updated!' };
  },

  delete: async ({ request }) => {
    const formData = await request.formData();
    const id = formData.get('id') as string;

    const index = notes.findIndex(n => n.id === id);
    if (index === -1) return fail(404, { error: 'Note not found', action: 'delete' as const });

    notes.splice(index, 1);

    return { success: true, action: 'delete' as const, message: 'Note deleted!' };
  }
};
```

```svelte
<!-- src/routes/notes/+page.svelte -->
<script lang="ts">
  import { enhance } from '$app/forms';
  import type { ActionData, PageData } from './$types';

  let { data, form }: { data: PageData; form: ActionData } = $props();

  let editingId = $state<string | null>(null);
  let createSubmitting = $state(false);
  let deleteSubmitting = $state<string | null>(null);
</script>

<h1>Notes</h1>

<!-- Success toast -->
{#if form?.success && form?.message}
  <div class="toast success" role="status">{form.message}</div>
{/if}

<!-- Create form -->
<section>
  <h2>New Note</h2>
  <form
    method="POST"
    action="?/create"
    use:enhance={() => {
      createSubmitting = true;
      return async ({ update }) => {
        createSubmitting = false;
        await update({ reset: true }); // Clear the form on success
      };
    }}
  >
    <div class="field">
      <label for="create-title">Title</label>
      <input
        id="create-title"
        name="title"
        value={form?.action === 'create' ? form?.values?.title ?? '' : ''}
        required
      />
      {#if form?.action === 'create' && form?.errors?.title}
        <p class="error" role="alert">{form.errors.title}</p>
      {/if}
    </div>

    <div class="field">
      <label for="create-body">Body</label>
      <textarea
        id="create-body"
        name="body"
        rows="3"
        required
      >{form?.action === 'create' ? form?.values?.body ?? '' : ''}</textarea>
      {#if form?.action === 'create' && form?.errors?.body}
        <p class="error" role="alert">{form.errors.body}</p>
      {/if}
    </div>

    <button type="submit" disabled={createSubmitting}>
      {createSubmitting ? 'Creating...' : 'Create Note'}
    </button>
  </form>
</section>

<!-- Note list -->
<section>
  <h2>Your Notes ({data.notes.length})</h2>

  {#each data.notes as note (note.id)}
    <article class="note">
      {#if editingId === note.id}
        <!-- Edit form -->
        <form
          method="POST"
          action="?/update"
          use:enhance={() => {
            return async ({ result, update }) => {
              if (result.type === 'success') {
                editingId = null;
              }
              await update({ reset: false });
            };
          }}
        >
          <input type="hidden" name="id" value={note.id} />
          <input name="title" value={note.title} required />
          <textarea name="body" rows="2" required>{note.body}</textarea>
          <div class="actions">
            <button type="submit">Save</button>
            <button type="button" onclick={() => editingId = null}>Cancel</button>
          </div>
        </form>
      {:else}
        <!-- Display mode -->
        <h3>{note.title}</h3>
        <p>{note.body}</p>
        <small>Updated: {new Date(note.updatedAt).toLocaleDateString()}</small>
        <div class="actions">
          <button type="button" onclick={() => editingId = note.id}>Edit</button>
          <form
            method="POST"
            action="?/delete"
            use:enhance={() => {
              deleteSubmitting = note.id;
              return async ({ update }) => {
                deleteSubmitting = null;
                await update();
              };
            }}
          >
            <input type="hidden" name="id" value={note.id} />
            <button
              type="submit"
              class="danger"
              disabled={deleteSubmitting === note.id}
              aria-label="Delete {note.title}"
            >
              {deleteSubmitting === note.id ? 'Deleting...' : 'Delete'}
            </button>
          </form>
        </div>
      {/if}
    </article>
  {/each}
</section>
```

Key patterns in this example:

- **Action tagging**: Each action returns an `action` property (`'create'`, `'update'`, `'delete'`) so the template knows which form's errors to display. Without this, a validation error from the create form would show in the edit form too.
- **Per-form loading state**: `createSubmitting` and `deleteSubmitting` are independent. Deleting one note does not disable the create button.
- **Inline editing**: The edit form appears in place of the note display. On success, `editingId` is cleared and the note returns to display mode.
- **Progressive enhancement**: Every form has `method="POST"` and proper `action` attributes. Without JavaScript, each submission triggers a full page reload -- ugly but functional. With `use:enhance`, the experience is smooth and seamless.

## Security: CSRF Protection and Input Sanitization

### Built-in CSRF Protection

SvelteKit automatically protects against cross-site request forgery (CSRF) attacks. On every form submission, SvelteKit checks that the `Origin` header matches the app's origin. If a malicious site tries to submit a form to your app, the `Origin` header will be different and SvelteKit will reject the request with a 403.

This protection is enabled by default. You do not need to add CSRF tokens to your forms. You can configure it in `svelte.config.js`:

```javascript
// svelte.config.js
export default {
  kit: {
    csrf: {
      checkOrigin: true // default: true
    }
  }
};
```

### Input Sanitization

Always sanitize user input before storing or displaying it. Form data is raw user input -- it can contain HTML, SQL, or script injections:

```typescript
import { fail } from '@sveltejs/kit';
import DOMPurify from 'isomorphic-dompurify';

export const actions: Actions = {
  create: async ({ request }) => {
    const formData = await request.formData();
    const title = formData.get('title') as string;
    const content = formData.get('content') as string;

    // Strip HTML tags from title (plain text only)
    const sanitizedTitle = title.replace(/<[^>]*>/g, '').trim();

    // If content allows HTML, sanitize it with DOMPurify
    const sanitizedContent = DOMPurify.sanitize(content, {
      ALLOWED_TAGS: ['p', 'b', 'i', 'em', 'strong', 'a', 'ul', 'ol', 'li'],
      ALLOWED_ATTR: ['href']
    });

    await db.insert(posts).values({
      title: sanitizedTitle,
      content: sanitizedContent
    });

    return { success: true };
  }
};
```

Svelte's template rendering (`{variable}`) automatically escapes HTML, so `<script>alert('xss')</script>` renders as literal text in the template. But if you use `{@html content}`, you must sanitize the content first.

## Redirects After Actions

Use `redirect()` from `@sveltejs/kit` to navigate after a successful action. Always use status `303` for POST-to-GET redirects (the standard HTTP pattern):

```typescript
import { redirect, fail } from '@sveltejs/kit';

export const actions: Actions = {
  create: async ({ request }) => {
    const formData = await request.formData();
    // ... validate and create the resource ...

    const newId = await createResource(formData);

    // Redirect to the new resource's page
    throw redirect(303, `/resources/${newId}`);
  }
};
```

**Why `throw`?** `redirect()` returns a `Redirect` object. You `throw` it to immediately exit the action and trigger the redirect. If you accidentally `return redirect(...)`, SvelteKit will treat it as action data, not a navigation.

**Why status 303?** After a POST request, you typically want the browser to make a GET request to the new URL. Status 303 ("See Other") tells the browser to do exactly that. This prevents the "re-submit form?" dialog if the user refreshes the redirected page.

## Key Takeaways

- Form actions are server-side functions defined in `+page.server.ts` under `export const actions` -- they handle POST requests and work without JavaScript
- The `default` action handles forms without a specific `action` attribute; named actions use `action="?/actionName"`
- Actions receive a `RequestEvent` with access to `request.formData()`, `cookies`, `locals`, `params`, and the full request context
- The `form` prop in `+page.svelte` contains the action's return value (`null` on initial load, populated after submission)
- Use `fail(statusCode, data)` to return validation errors -- this preserves form values in `use:enhance` and sets the correct HTTP status
- Named actions (`?/create`, `?/update`, `?/delete`) enable multiple independent forms on one page, each targeting a different server handler
- `use:enhance` upgrades forms to AJAX submission without page reload; the server code is identical with or without it
- Custom `enhance` callbacks give you pre-submit validation, loading states, and post-submit result handling
- Validate form data with `formData.get()`, `Object.fromEntries()`, or schema libraries like Zod and Valibot
- SvelteKit includes automatic CSRF protection by checking the Origin header -- no tokens needed
- Always sanitize user input before storing it; Svelte auto-escapes in templates but `{@html}` is raw
- Use `throw redirect(303, url)` after successful mutations to implement the POST-Redirect-GET pattern
